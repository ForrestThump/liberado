## Cross-session insights distilled

- **The docs-as-you-go discipline is paying off.** This arc kept `ARCHITECTURE.md`, `AGENTS.md`,
  `docs/interface.md`, and the decision log current as features landed, so the Dream had little to
  reconcile. The lesson worth keeping: de-staling at landing time leaves only the *status framing* and
  *one broken stub* for consolidation — not a backlog of contradictions.
- **"Verify independently after a subagent" is now a proven, repeatable loop**, not a one-off:
  read the code → `cargo test` → live two-turn smoke asserting continuity + a persisted ULID `.jsonl`.
  It has caught real regressions (the `liberado-orchestrator` dep removal that "looked safe" but broke
  the build). Promoted into the handoff so it survives.
- **Two pitfalls in this repo are environmental and recur**: Windows case-insensitivity (the
  `handoff.md`/`HANDOFF.md` collision that produced the broken stub) and SSE/`EventSource` semantics
  (the `error`→`failed` rename). Both are now captured in the handoff so they aren't relearned.
- **Daemon-first (Decision 2) is now concretely realized, not aspirational.** One process hosts the
  watch loop + chat + API; `server` is a library; interfaces (`webui`, `liberado chat`, future TUI)
  are clients. The decision log predates this; the architecture status now reflects it.
- **The store's one irreversible choice is honored in code.** ULID-at-append-inside-the-lock (so
  file-order == id-order) is exactly what the spec marked non-retrofittable, and `jsonl.rs` implements
  it that way. Everything else (index, projections, SQLite/Postgres) stays deferred and additive.
